## 一、这是什么

一个跑在 **Windows + 微信 PC 客户端**上的个人自动化工具集，用于**维护已经建立联系的客户**：

自动接收并归档聊天记录 → AI 生成回复草稿 → 键盘驱动发出 → 网页看板查看与管理。

它面向的场景很小：一个人维护几十到几百个已知客户，避免漏回消息、忘记跟进。
**它不是营销工具，不提供任何"获客"能力，也不鼓励扩张式添加。**

## 二、功能模块

| 模块 | 说明 |
|---|---|
| 消息归档 | 定时读取本地会话，落库到 SQLite，支持上下文、媒体下载、卡片解析 |
| AI 自动回复 | 客户发来消息后按合并窗口聚合成一条，交给大模型生成回复，**默认全关、按会话单独开启** |
| 首条自我介绍 | 好友通过后延迟 60~120 秒发一条自我介绍；客户先开口则自动取消 |
| 朋友圈互动 | 读取朋友圈，可对指定客户自动点赞/评论（默认关，评论需手动确认） |
| 批量加好友 | 从 CSV 导入名单，按每日上限与随机间隔逐条发送申请（默认关） |
| 主动触达 | 定时给长期沉默的客户发一条问候，承接上次聊到的具体内容（每天 8:00–21:00，条间 10–30 分钟、每会话冷却期与累计次数上限）；`activate.py` 是手动版 |
| 人工接管 | 客户回复出现明确意向时，自动通知指定的群聊 / 同事（真人），暂停该会话自动回复并交出对话，避免机器人把线索聊丢 |
| 活动触达 | 在后台写死通知文案、指定发送时间与对象（群聊/私聊），到点自动逐个发出；过点只在宽限期内补发，失败不重试 |
| 网页看板 | 消息 / 朋友圈 / 加好友 / 维护任务 / 人工接管 / 活动触达 六个页面，可开关每个会话的托管状态、勾选接管通知对象、编排定时活动 |
| 公开信息采集 | `scraper/` 下独立的合规采集框架，仅采集企业**主动公开**的商业联系方式 |

## 三、技术路线（为什么这么做）

- **键盘驱动，而非注入**：通过模拟真实键鼠操作客户端，不向进程注入代码、不 hook API。
  注入类方案在新版客户端上既不稳定，封号风险也更高。
- **消息读取走本地数据库**：客户端界面是自绘的，读不到控件；消息最终从本地加密库
  解密读取（依赖 `wechatauto-replica`）。
- **UI 独占门**：客户端只有一份焦点，所有会抢占前台的操作（发送、刷新朋友圈、导航）
  必须经同一把锁串行，避免互相打断。
- **解密缓存按进程隔离**：`wechatauto` 默认把解密副本写进一个全进程共享的临时目录，
  多进程同时重建会触发 Windows `[WinError 5] 拒绝访问`。项目统一经 `db_gate.get_db()`
  取库：每个进程一份私有副本目录 + 一个实例，互不干扰（详见 `RUNBOOK.md`）。
- **发出去才算发**：键盘动作跑完不等于消息真的发出，每次发送后回读数据库确认，
  确认失败落 `failed` 而不是记一条假成功。
- **发送前判定"谁发的"**：只能靠发送者标识，不能靠编号（编号是分片内的行号，
  换设备就变，踩过坑，详见 `RUNBOOK.md`）。

## 四、目录结构

```
auto_reply.py        自动回复主进程（收消息 → AI 生成 → 发送 三条流水线）
activate.py          存量客户激活（手动跑一遍，参数默认取 config）
outreach_core.py     主动触达的共享内核（话术意图 / 上下文 / 候选规则）
handoff.py           人工接管（意向判定 / 通知目标 / 接管记录）
progress_bar.py      终端单行进度条（TTY 原地重绘，日志只留一行汇总）
wx_recv_bridge.py    收消息桥：解密本地库 → 增量入库 → 媒体落地
wechat_ui.py         键盘驱动发送层（搜索/进会话/粘贴/发送/回读校验）
dashboard.py         网页看板（Flask，2 秒轮询）
monitor_store.py     统一消息库（SQLite）读写
ui_gate.py           微信 UI 独占锁（跨进程）
db_gate.py           微信解密库隔离门（一进程一份副本 + 进程内单例）
ai_client.py         AI 调用与系统提示词（OpenAI 兼容接口）
friend_add.py        批量加好友
moment_ops.py        朋友圈读取与互动
export_history.py    聊天记录导出
scraper/             公开商业信息采集（独立，可单独运行）
knowledge/           产品/业务知识库（按 ## 小节检索注入提示词）
config.json          运行配置（不含密钥）
ai_secrets.json      AI 密钥与模型配置（**已被 .gitignore 忽略**）
RUNBOOK.md           运维手册：架构、事故记录、验收清单
COMMANDS.md          命令与接口速查
```

## 五、运行前提

- Windows 10/11，微信 PC 客户端已登录（保持在前台可用）
- Python 3.10+，`pip install -r requirements.txt`
- 需要自行准备 `ai_secrets.json`（模型地址与密钥），**不要提交到公开仓库**
- 首次运行需全量解密本地库，可能耗时数分钟；`dashboard.py` 与 `auto_reply.py`
  可以同时运行，各自使用独立的解密副本目录
- 报 `[WinError 5] 拒绝访问` 时先确认所有 python 进程都用上了新版 `db_gate`；
  旧进程残留可作废后清理：`python -c "import db_gate; print(db_gate.cleanup_stale())"`

## 六、明确的合规边界

本项目**只允许**用于以下场景：

- 维护你**已经建立联系**的客户/联系人；
- 对方对自动化回复**知情且不反对**；
- 内容真实、不夸大、不承诺无法兑现的效果；
- 遵守频率限制（条间随机间隔、每会话冷却与累计次数上限），不做批量骚扰。
- 人工接管通知只发给**自己团队内部**的群聊 / 同事，不发给客户或外部群。
- 活动触达的文案由使用者自行撰写并**自行承担内容责任**，只发给已建立联系且
  未表示拒绝的对象。

以下行为**一律禁止**，且不属于本项目的设计目的：

- ❌ 无差别添加陌生人、批量爬取通讯录、群发营销信息
- ❌ 冒充真人身份进行欺骗（AI 被问起时必须承认）
- ❌ 采集、出售、传播他人个人信息
- ❌ 用于诈骗、赌博、色情、医美贷等任何违法业务
- ❌ 多开养号、规避平台风控、对抗检测
