# knowledge/ —— 产品知识库（AI 销售的资料来源）

这个目录是 AI 回复时唯一允许引用的产品事实来源。**AI 被明确禁止编造库里没有的功能、价格、案例**——答不上来会说"我核实一下再回你"，而不是瞎编。

## 文件格式

- 一个 `.md` 文件 = 一个主题（如 `产品总览.md`、`价格方案.md`、`常见问题.md`）
- 用 `## 小节标题` 分段，**每个小节是一个检索单元**（标题也算检索词，权重更高）
- 纯文本/Markdown 均可；不需要特殊语法

```
## 平台是什么
我们是一个面向空间设计行业的 SaaS 平台…… AI照明工作站，简称A站

## 核心功能
1. …
```

## 检索逻辑（当前 v1）

客户消息进来时，按「客户原话 + 沟通意图 + 客户标签」做中文二元切词，与每个小节算重合度，取相关度最高的前 N 个小节（`config.json` 的 `knowledge.top_k`，默认 3）注入系统提示词。**相关度都为 0 时一个小节都不注**——不相关的资料硬塞反而干扰回复。

改完文件**下一条消息即生效**（按 mtime 自动重载，不用重启 auto_reply）。

## 拓展路线（按需逐步上，不要一步到位）

| 阶段         | 做法                                                                                         | 什么时候需要                               |
| ------------ | -------------------------------------------------------------------------------------------- | ------------------------------------------ |
| v1（已落地） | 本目录 `.md` 文件 + 关键词检索                                                               | 现在                                       |
| v2           | 每个小节加 front-matter：`适用标签: vip,new` / `更新: 2026-10-15`，按客户标签过滤 + 过期提醒 | 客户分层变细、资料开始互相干扰时           |
| v3           | 向量检索：embedding 模型（本地 bge-m3 或 API）+ sqlite-vec 存向量，语义匹配替代关键词        | 关键词漏检明显（客户换种说法就检索不到）时 |
| v4           | 资料库接入：PDF/docx/网页批量解析切片入库（chunk 500 字 + 重叠 50）                          | 资料量大到手工维护 md 不现实时             |
| v5           | 反馈闭环：AI 答不上/答错的自动记「知识缺口」清单，人工补库                                   | 运行一段时间后有真实缺口数据后再做         |

原则：**每阶段只解决当阶段的痛点**，v1 的关键词检索对几十篇资料完全够用，别一上来堆向量库。
